# Theme identity refactor — rclabs.uk as single source of truth

## Goal

Make the rclabs.uk product-site design system the single theme identity for every first-party UI. One shared token source; each app keeps its local alias names. Delete dead theme code and font drift. Prevent palette drift with a check that fails on divergence.

## Decisions (confirmed)

| Decision | Choice |
| --- | --- |
| Enforcement | Shared token file + per-app aliases; values come from one source |
| Surfaces | product-site, atheros-search-ui, schema-migrator-ui (web+Electron), Keycloak login, Rust `/dashboard` (`static/index.html`) |
| Cleanup | Dead theme tokens, leftover theme-switch scaffolding, IBM Plex Mono, Google Fonts loading |
| Out of scope | Grafana dashboards, product renames (Bedrock/atheros naming), WCAG conformance claims, GitOps/cluster mutation |

## Architecture

### Why not a shared npm package

`apps/schema-migrator/` and `apps/integration-console/` are git submodules with independent `package.json`/lockfiles/CI. Parent-repo paths are not importable at their build time. A published workspace package is disproportionate for five token files.

### Recommended: single JSON source + generator + drift check

```
theme/
  rclabs.tokens.json          # single source of truth (canonical hexes + role names)
scripts/
  sync_theme_tokens.py        # write/refresh each surface's token block from JSON
  check_theme_tokens.py       # fail if any surface's resolved hexes diverge (or: sync --check)
```

- **Source of truth:** `theme/rclabs.tokens.json` — role → hex (and font stacks), derived from `apps/product-site/docs/design-system.md`.
- **Delivery:** `scripts/sync_theme_tokens.py` regenerates only the token block in each surface's existing file (keeps local alias names). Commit the generated blocks; apps never hand-edit hexes.
- **Drift gate:** `check_theme_tokens.py` (or `sync_theme_tokens.py --check`) parses each surface, resolves aliases to hexes, compares to the JSON. Wire into `make lint` / `make test` or a new `make theme-check`.
- product-site `site.css` is both a consumer (token block generated) and the living design-system reference; `docs/rclabs-theme.md` and `design-system.md` keep pointing at the same palette values (docs updated to name `theme/rclabs.tokens.json` as the machine source).

### Other deletes

- Vestigial `for (const theme of ['dark'])` loops in `apps/product-site/tests/site.spec.ts` (7 sites) and `layout.spec.ts` — flatten to the dark-only body. **Keep** negative tests that saved light/system values are ignored.

## Implementation tasks

1. Add `theme/rclabs.tokens.json` with core + semantic + font roles and hex values (table above).
2. Add `scripts/sync_theme_tokens.py` and `scripts/check_theme_tokens.py` (or one script with `--check`).
3. Add `make theme-check` (and call it from an existing lint/test path if one is appropriate).
4. Point `docs/rclabs-theme.md` and `apps/product-site/docs/design-system.md` at the JSON as the machine-readable source; keep the human palette tables in sync.

1. Run sync against product-site `site.css`, search `tokens.css`, migrator `tokens.ts` primitives, Keycloak `custom-login.css`, `static/index.html`.
2. Resolve contrast-sensitive changes (`on-accent` → `#102010`, `border` → `#7D8278`) and update any tests that assert the old hexes.

3. Product-site: flatten single-theme test loops; collapse product accent aliases if cheap.

## Risks

1. **Contrast regressions** when unifying `on-accent` and `border` — run product-site and search contrast tests first; adjust only if a target fails, and re-calculate 7:1/3:1.
2. **Submodule workflow** — schema-migrator and integration-console need their own commits before the parent can pin SHAs; keep theme commits boring and split parent vs submodule if review requires it.
3. **Keycloak ConfigMap is GitOps** — edit source YAML/CSS in-repo only; do not mutate the cluster.
4. **Tests assert exact hexes** — `theme.spec.ts`, `tokens.test.ts`, `accessibilityCodex.test.ts`, product-site site tests, keycloak `login.spec.cjs` may encode old values; update expected hexes deliberately.
5. **`compatibilityTokens` collapse** is the largest mechanical risk in migrator `styles.css` (many `var(--muted)` etc.); either migrate carefully or delete only unused aliases in this pass.
6. **Graph/visual polish** — search graph colors that depended on `accent-ink #090909` vs `#102010` may shift subtly; visual review via `npm run review` / e2e screenshots.

## Out of scope

- Grafana dashboard JSON thresholds and any Grafana skin.
- Renaming “Bedrock Schema Migrator” / “atheros” product strings (theme/colour only; logo palette is in scope).
- WCAG conformance claims or completing the manual AT matrix.
- Deploying Keycloak/ConfigMaps or interactive cluster changes.
- Committing/PR unless the user asks.

## Success criteria

1. One JSON file holds every core/semantic hex; no surface hand-copies palette values.
2. `make theme-check` (or equivalent) fails if any surface drifts.
3. All five first-party UIs render the RCLabs dark palette (page `#090909`, accent `#A3E6A3`, text `#F5F5F2`).
4. No Google Fonts CDN, no IBM Plex, no GitHub-dark dashboard palette, no unused theme tokens from the delete list.
5. Existing automated suites above pass; dark-only locks remain in force.
